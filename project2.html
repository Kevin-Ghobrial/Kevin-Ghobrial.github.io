Technical Report

System Overview

  • Input: Chess.com username
  • Output: Game analysis report (accuracy, blunders, trends)
  • Core Engine: Stockfish (via python-chess.engine)

Architecture

Pipeline Overview: Client → API Fetcher → PGN Parser → Stockfish Evaluator → Data Aggregator → Report Generator

Workflow

  1. Fetch all archives from Chess.com API.
  2. Parse each PGN for metadata and move list.
  3. Run Stockfish analysis for every move to get evaluation and best move.
  4. Classify move quality (Best / Good / Inaccuracy / Mistake / Blunder).
  5. Aggregate metrics across games for trend visualization.

Key Metrics

  • Centipawn Loss (CPL): |Eval(player) − Eval(best)|
  • Move Accuracy %: Derived from cumulative CPL per game
  • Blunders/Game: Count of moves exceeding CPL threshold
  • Opening Success Rate: Win rate by ECO code
  • Performance Trends: Accuracy over time, by color, by opening

Design Choices

  • Engine Time Limit: 100ms per move for speed vs. accuracy balance.
  • Caching: Stores evaluated games to avoid redundant analysis.
  • Parallelism: Uses multi-threading for faster Stockfish calls.
  • API Handling: Implements rate limiting with exponential backoff.

Challenges

  • Handling thousands of moves efficiently.
  • Ensuring evaluation consistency across variable positions.
  • Optimizing for time without losing analytical accuracy.

Future Work

  • Integration with Lichess and FIDE data.
  • Natural language summaries (“Recurring mistake: missed pins in the middlegame”).
  • Interactive web dashboard with user statistics and charts.

Usage Example
